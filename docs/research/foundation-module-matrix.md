Research for [issue #926](https://github.com/liberusoftware/ecommerce-laravel/issues/926) (part of #925).

**Question:** which boilerplate foundation modules does `ecommerce-laravel` need, and for each one, what in this repo's `app/` does it replace?

## 0. Facts that shape every row below

These are load-bearing, so they are stated before the matrix.

### 0.1 The catalog has 28 modules, not 29

`projects/boilerplate/BOILERPLATE.md` §3 "Foundation module catalog" is a 28-row table. `projects/boilerplate/core/` holds 29 files, but one is `README.md` — an index whose table also lists exactly 28 modules. The issue title's "29" counts the index file. **Flagged, not resolved:** if #925 tracks 29 epics, one of them has no catalog row.

### 0.2 The 28 `core/*.md` specs are a template, not 28 different specs

`md5sum` over `projects/boilerplate/core/*.md` gives 29 distinct hashes, but reading them shows the difference is confined to three header lines (`# Boilerplate: <Name> domain packages`, `**Composer package:**`, `**Capability:**`) plus the capability sentence. The "Ownership and implementation plan" and "Verification and consumer contract" bodies are byte-identical boilerplate across `application-core.md`, `module-manager.md`, `identity.md`, `two-factor-authentication.md`, `sessions-and-devices.md`, `jetstream-bridge.md`, `profiles.md` and `organizations-and-teams.md` (all read in full).

**Consequence:** the per-module specs carry no per-module requirements. The only normative per-capability text lives in `BOILERPLATE.md` §§4–14. Every "what it provides" cell below is therefore sourced from `BOILERPLATE.md` and from the installed package's actual `src/`, not from `core/<module>.md`.

### 0.3 `BOILERPLATE.md` is physically duplicated three times

`grep -n '^## '` returns the full section run `## Canonical Application Foundation Scope … ## 20. GitHub issue mapping` three times, at lines 3–329, 330–656 and 657–982, under a single `# Liberu Laravel Boilerplate` H1. The three copies appear identical. **Flagged as a defect in the source document**, not resolved here.

### 0.4 Package names differ across all three sources — pick one before writing adoption tickets

| Source | Name for the settings capability |
| --- | --- |
| `projects/boilerplate/core/settings.md` | `module-settings` |
| `boilerplate-laravel/composer.json:258` | `liberusoftware/settings` |
| `boilerplate-laravel/docs/CONFORMANCE.md` §3.3 | presentation adapters become `module-settings-filament`; core packages stay bare |

`CONFORMANCE.md` §3.3 also documents renames already decided but not fully landed (`identity` → `identity-core`, `application-core` → `application`, `foundation-filament` dissolved into `module-sessions-devices-filament` + `module-module-manager-filament` + a host-owned `Support/ThemeColors`). The **Package** column below uses the name that actually resolves today — the one in `boilerplate-laravel/composer.json`.

### 0.5 The installed modules are thin. Most are contracts + one or two support classes

Full file listing of `boilerplate-laravel/modules/*/src/**/*.php` (208 files across 40 packages). Representative sizes:

- `modules/webhooks/src/` — 4 files: `WebhooksServiceProvider`, `Support/RetrySchedule`, `Support/SigningSecretVault`, `Support/WebhookSigner`. No endpoint model, no delivery job, no retry command.
- `modules/notifications/src/` — 3 files: provider, `Support/DeliveryRetry`, `Support/NotificationPolicy`.
- `modules/api-access/src/` — 3 files: provider, `Support/IdempotencyStore`, `Support/TokenPolicy`.
- `modules/feature-flags/src/` — 2 files: provider + `Support/FlagEvaluator`.
- `modules/sessions-devices/src/` — 2 files: provider + `Queries/SessionReader`.

Only a minority ship models/actions that literally replace a class here: `identity-socialstream` (7 actions + `Models/ConnectedAccount` + `Policies/ConnectedAccountPolicy`), `jetstream-bridge` (5 Fortify actions + `Actions/Jetstream/DeleteUser`), `organizations-teams` (4 models, 3 actions, `TeamPolicy`, `CurrentTeamResolver`), `roles-permissions` (`Models/Role`, `Models/Permission`, `RolePolicy`, `PermissionRegistry`, `BreakGlass`, `SeparationOfDuty`, `AnyTeamRoleLookup`), `module-manager` (15 files), `theme-support` (10 files), `currency-context` (12 files incl. `ValueObjects/Money`), `settings` (`Settings/SiteSettings`, `Services/ScopedSettings`), `search` (8 files), `application` (9 files).

So the honest verdict for many rows is **"adopt the contract, keep the implementation"**, not "delete this directory".

### 0.6 The end-state host boundary

`boilerplate-laravel/app/` contains **5 PHP files**: `Models/User.php`, `Providers/Filament/AdminPanelProvider.php`, `Providers/Filament/AppPanelProvider.php`, `Filament/ModulePlugins.php`, `Support/ThemeColors.php` — as `boilerplate-laravel/docs/FOUNDATION_MODULE_MATRIX.md` § "Host boundary" states. `ecommerce-laravel/app/` contains **400 PHP files**. Most of that gap is ecommerce domain code, which `architecture/MODULES.md` §5.5 says belongs in product packages, not `app/` — but that is issue #925's scope, not this one.

### 0.7 `ecommerce-laravel` currently installs zero `liberusoftware/*` packages

`composer.json:10-33` requires no foundation module and no `liberusoftware/composer-installer`. `architecture/MODULES.md` §6.1 makes that installer a prerequisite for any `liberu-module` type package, and §6.2 requires the resulting `/modules` tree to be committed. **Adopting any row below is blocked on adding the installer plugin first.**

## 3. Divergences this repo has that no module covers

Findings that surfaced during the audit and that adoption would break, lose, or leave behind.

1. **`app/Providers/SocialstreamServiceProvider.php` is never registered.** It is absent from `config/app.php:158-179`, and a repo-wide grep for `SocialstreamServiceProvider` matches only its own definition. All 8 files in `app/Actions/Socialstream/` are therefore dead — Socialstream falls back to its package defaults. `identity-socialstream` would supersede 7 of them (`modules/identity-socialstream/src/Actions/`) plus `app/Models/ConnectedAccount.php` and `app/Policies/ConnectedAccountPolicy.php`; `app/Actions/Socialstream/CreateUserWithTeamsFromProvider.php` has no counterpart. **Fix the wiring or delete the directory before migrating either way.**

2. **`app/Providers/TeamServiceProvider.php` is genealogy code from another product.** It is registered (`config/app.php:176`) and binds eleven `FamilyTree365\LaravelGedcom\*` classes to `App\Models\{Addr,BatchData,Chan,Family,FamilyEvent,FamilySlgs,Person,PersonAlia,PersonAsso,PersonEvent,Subm}` — **none of which exist** in `app/Models/`, and `familytree365/*` is not in `composer.json`. Harmless only because `bind()` is lazy. It has nothing to do with teams and belongs in no module.

3. **Two competing settings systems, one of them broken.** See row 25: `App\Settings\GeneralSettings` (spatie, works) versus `SiteSetting`/`SiteSettingsService`/`SiteSettingController` (`routes/web.php:204-206`), whose caching reads a `config/site-settings.php` that does not exist.

4. **Permission naming is internally inconsistent before any module is involved.** `config/filament-shield.php:100-104` says `separator: ':'`, `case: 'pascal'`; `app/Policies/*.php` check flat `view_any_product` strings. Whichever wins, both fail `PermissionRegistry`'s `{module}.{resource}.{action}` pattern.

5. **`spatie/laravel-permission` version skew**: `^8.3` here (`composer.json:29`) vs `^7.0` in the reference app (`boilerplate-laravel/composer.json:272`). `roles-permissions` is unverified against v8.

6. **Money is stored as floats and bare integers.** `app/Models/Currency.php:43,62,70` and `orders.total_amount` as `integer` with no currency column (`database/migrations/2023_09_26_113752_create_orders_table.php:20`) contradict `BOILERPLATE.md` §11.

7. **The CSP is this repo's own work.** `app/Http/Middleware/SecurityHeaders.php:19-28` — the `application` module explicitly declines to ship one.

8. **The password policy is this repo's own work.** `app/Providers/AppServiceProvider.php:31-46` — no foundation module has an equivalent.

9. **`app/Modules/` is unused scaffolding.** No concrete module implements `ModuleInterface`; `config/modules.php:66` enables none. 1 095 lines to delete, not migrate.

10. **`app/Filament/Admin/Resources/` has duplicate menu resources**: `MenuResource.php` and `MenuItemResource.php` sit beside `Menus/MenuResource.php`. Unrelated to any module, but it will confuse a Filament plugin migration.
